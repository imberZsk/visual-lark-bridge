# 样式规范

## 样式归属

- `src/styles.css` 只保留根变量、应用壳、侧栏、页面头和跨页公共面板规则。
- 组件专用样式放在相邻 `ComponentName.css`，由组件显式导入；选择器必须绑定组件根 class，禁止无边界覆盖全部 antd 内部结构。
- 多处复用的间距和稳定尺寸使用有语义的 CSS 变量；布局间距遵循 `ui-standards.md` 的 4px 梯度。

## JSX 行内样式边界

- 业务组件默认禁止 `style={{ ... }}`、`styles={{ ... }}` 和通过 `*Props` 传入固定 style。固定布局、尺寸、间距、字号、颜色、背景、边框、圆角、阴影和滚动规则必须进入相邻 CSS。
- `width: "100%"`、`marginBottom: 0` 和 `color: token.colorTextSecondary` 同样属于固定视觉规则，不能因代码短就留在 JSX。
- antd 的 `block`、`danger`、`type`、`size`、`status`、`Typography type` 和语义 `Tag color` 属于组件 API，可以使用。
- 唯一例外是运行时才能确定且无法由 class/CSS 自定义属性表达的数据驱动几何值；使用时必须注释数据来源和不能使用 CSS 的原因，不得夹带固定间距或颜色。

## 颜色与覆盖

- 固定外观优先使用 `--ant-*` CSS 语义变量；日志代码画布等确需独立深色语境时，集中定义业务语义变量，不在选择器中散落色值。
- 不使用 `!important` 作为默认方案。覆盖 antd 内部结构时必须限定业务根 class，并说明 DOM 或优先级原因。
- 新增视觉值前先搜索已有变量和相邻组件；不能表达需求时先补充规范，再引入新值。

## 完成前检查

1. 搜索本次组件中的 `style=`、`styles=`、裸色值和非规范布局间距。
2. 确认组件 CSS 已由业务根 class 限定，专用规则没有回流全局 CSS。
3. 运行格式检查、相关测试、完整测试和构建。
4. 使用无头 Electron E2E 生成关键页面截图，同时检查浅色、深色和最小窗口。

# UI 与交互规范

## 设计基础

- 修改或新增 UI 前必须同时阅读本文件与 `style-standards.md`，二者是实现和验收约束。
- Ant Design 是唯一基础设计系统；优先使用 antd 组件、公开语义属性、主题 token 和 `@ant-design/icons`，不引入第二套颜色或间距工具链。
- 桌面控制台保持安静、紧凑、便于重复扫描。信息层级依靠间距、字号、字重和语义色，不依靠渐变、大阴影或装饰卡片。

## 间距与层级

- 布局间距只使用 `4 / 8 / 12 / 16 / 24 / 32px`：4px 表示紧密关联，8px 表示同组元素，12px 表示关联内容，16px 表示子区块，24px 表示同级模块，32px 表示主要区域。
- 禁止临时创造 6px、9px、10px、14px、18px 等布局间距。字号、行高、控件高度、固定列宽和响应式断点不属于布局间距，但必须集中定义并说明用途。
- 标签到控件沿用 antd `Form.Item` 节奏；控件到说明文字 8px，同组重复项 8px，说明到列表及列表到新增操作 12px，同级字段或模块 24px。
- 页面只使用一个主内容面板；卡片仅用于独立重复项、弹层或确需边界的工具，禁止卡片嵌套卡片。

## 颜色与组件

### Visual Worktree 标准色板

所有桌面项目使用 Ant Design 默认 seed `colorPrimary: #1677ff`，再分别通过 `defaultAlgorithm` / `darkAlgorithm` 派生主题；禁止按主题手写另一套 `colorPrimary`。当前锁定的关键结果如下：

| 语义                 | 亮色      | 暗色      | 使用场景                       |
| -------------------- | --------- | --------- | ------------------------------ |
| `colorPrimary`       | `#1677ff` | `#1668dc` | 主按钮、当前导航、焦点、链接   |
| `colorPrimaryHover`  | `#4096ff` | `#3c89e8` | 仅用于 hover，不能作为暗色主色 |
| `colorPrimaryActive` | `#0958d9` | `#1554ad` | 按下态                         |
| `colorPrimaryBg`     | `#e6f4ff` | `#15325b` | 低强度选中背景                 |
| `colorSuccess`       | `#52c41a` | `#49aa19` | 成功、完成                     |
| `colorWarning`       | `#faad14` | `#d89614` | 警告、需注意                   |
| `colorError`         | `#ff4d4f` | `#dc4446` | 错误、阻断、危险操作           |
| `colorBgLayout`      | `#f5f5f5` | `#000000` | 页面底层                       |
| `colorBgContainer`   | `#ffffff` | `#141414` | 侧栏和主要容器                 |
| `colorBgElevated`    | `#ffffff` | `#1f1f1f` | 卡片、弹层、浮层               |
| `colorBorder`        | `#d9d9d9` | `#424242` | 控件和主要边界                 |

- 业务组件必须消费 Ant Design token 或与上表一一映射的语义 CSS 变量，不直接写主色、状态色和主题中性色。
- 启动页无法读取 React token 时，允许静态使用上表的 `colorPrimary`；亮色为 `#1677ff`，暗色为 `#1668dc`。
- `#4096ff` 只能表示亮色 hover；不得再作为暗色默认主色、常驻图标色或 loading 色。
- 图表、代码高亮和第三方平台品牌色属于独立数据语义，必须使用专用变量，并且不能覆盖应用交互主色。

- 正文、次级文案、边界、背景和状态分别使用 Ant Design 的 `colorText*`、`colorBorder*`、`colorBg*`、`colorFill*`、`colorSuccess/Warning/Error/Info` 语义 token。
- 红色只表示错误、阻断或危险操作；主色只用于当前导航、主要操作和交互焦点。
- 布尔值使用 Switch，模式使用 Segmented，选项集使用 Select，数字使用 InputNumber，纯图标按钮必须有 `aria-label` 或 Tooltip。
- 同类列表新增操作使用全宽虚线按钮；删除操作位于稳定行尾并使用 `danger`，不得直接给图标写固定灰色或红色。
- 内容侧栏的品牌区只显示产品名和副标题，不显示应用 Logo；应用图标只用于冷启动、Dock、安装包和系统级品牌入口，避免在狭窄导航中重复占位。

## 验收清单

1. 同类模块是否使用相同结构、间距变量和操作位置。
2. JSX 是否出现固定间距、布局、字号、颜色、边框、圆角或阴影；出现则迁移到相邻 CSS。
3. 明暗主题下正文、弱化信息、边界和状态是否仍有足够对比度。
4. 最小 Electron 窗口下是否无重叠、裁切、横向溢出或不可达操作。
5. loading、空数据、错误、禁用、hover 和 focus 状态是否完整。
6. 是否补充相关测试，并通过真实构建、完整测试和无头 E2E。
7. E2E 必须截取关键页面，逐张检查对齐、间距、文字截断、颜色层级和操作可达性。

## 启动与图标

- Electron 冷启动在 React 首次提交前使用静态主题背景、居中的 `112px` 项目图标和图标下方的 Ant Design 默认四点 `Spin` 形态；loading 容器为 `20px`、单点为 `9px`、与图标间距为 `16px`，并适配明暗主题和减少动态效果设置。
- 开发态 macOS Dock 和跨平台窗口图标必须使用仓库内 `1024px` 透明项目 PNG，打包态继续使用 `.icns/.ico` 等平台安装图标；不得显示 Electron 默认图标，也不得用低分辨率启动资源反向生成安装图标。
